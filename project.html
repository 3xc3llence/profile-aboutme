Featured Project

Betting Payments API Flow

Overview

A Postman collection called Betting flow that models how a betting company handles money using the MoMo Open API. A customer joins, pays in to place a bet, and if they win, the company validates their account and pays out the prize. It is split into two folders: Collections for the user side and Disbursements for the company side.

The problem I solved

Payment integrations have many dependent steps, and each one needs a valid token, a valid account and a confirmed status before the next can run. I turned that into a clear, ordered and repeatable test flow, so the whole journey from deposit to payout can be checked end to end.

Features

Collections (user side)

  1. 1. Get Collections Token
    The customer gets an access token to log in and use the API.
  2. 2. Get Customer Info
    Fetch the account holder details.
  3. 3. Check Account Active
    Confirm the depositor account is valid.
  4. 4. Request To Pay (Bet Stake)
    The customer pays money in to the betting company, to use for betting.
  5. 5. Check RequestToPay Status
    See whether the payment succeeded.

Disbursements (company side)

  1. 6. Get Disbursement Token
    The company gets its own access token.
  2. 7. Check Account Active (Winner)
    Validate the winner account holder status first.
  3. 8. Payout Transfer
    If the account is valid, pay the winnings with the transfer endpoint.
  4. 9. Check Payout Status
    Confirm the payout went through.

Screenshots

Request 01 in Postman: a POST to {{baseUrl}}/Collection/token/. The base URL is stored as an environment variable.

Technologies used

  • Postman
  • REST APIs
  • MoMo Open API
  • Environment variables
  • Token authorization
  • JSON

What I learned

  • How token-based authorization protects API requests, and how to set it up in Postman.
  • How to use environment variables like baseUrl so one collection works in different environments.
  • Why a company validates an account before sending money, and how requests depend on each other.
  • How to check payment status after sending a request, since payments are not always instant.
